# 채널 접근 권한

[Chrome 등록](browser-pairing.md) · [투두 17](https://github.com/freevue/flex-mcp/issues/17) · [투두 8](https://github.com/freevue/flex-mcp/issues/8)

서버는 등록된 Chrome 채널을 연결 키로 찾습니다. 서버에 사용자 이름, MCP 클라이언트 이름, 사번이나 조회 대상 URL을 보내지 않습니다. 이름을 알아도 채널 권한을 얻지 못합니다.

MCP 초기화, 도구 목록과 코드 승인은 연결 키가 없어도 요청할 수 있습니다. 서버는 만료하지 않은 일회용 코드만 승인합니다. 처음 연결 키는 확장이 등록을 받으면 사용할 수 있습니다. [추가 연결 키](browser-pairing.md#연결된-확장에-에이전트-추가)는 승인 직후 같은 채널에서 사용할 수 있습니다. 조회와 소켓 상태 도구는 유효한 연결 키가 있어야 동작합니다.

서버는 요청을 보낼 때 등록과 소켓을 확인합니다. 답을 받으면 같은 연결과 요청인지 다시 확인합니다. 확장이 등록을 바꾸거나 해제하면 이전 채널의 모든 연결 키와 추가 코드를 무효화합니다. 이전 연결에서 대기한 조회도 끝냅니다.

Flex 로그인은 승인한 브라우저에 남습니다. 실제 조회 코드는 현재 Flex 계정이 연결한 계정과 같은지 확인합니다. [실조회 범위](reading-boundary.md)를 따릅니다.

| TC | 조건 | 기대 결과 |
| --- | --- | --- |
| TC-F-ACCESS-CONTROL-01 | 두 채널의 키로 같은 서버를 조회합니다. | 각 키는 해당 채널의 결과만 받습니다. |
| TC-F-ACCESS-CONTROL-02 | 없는 키, 폐기한 키와 다른 등록 ID로 각각 요청합니다. | 조회 결과를 보내지 않습니다. |
| TC-F-ACCESS-CONTROL-03 | 응답을 기다리는 중에 등록을 해제합니다. | 이전 응답을 전달하지 않습니다. 다른 채널은 유지합니다. |
| TC-F-ACCESS-CONTROL-04 | 다른 Flex 계정으로 바꾼 뒤 실제 조회를 합니다. | 이전 계정의 조회를 막습니다. 실조회 검증은 별도입니다. |
