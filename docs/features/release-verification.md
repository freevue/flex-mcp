# 서버와 확장의 최종 배포 검증

[투두 6](https://github.com/freevue/flex-mcp/issues/6) · [서비스 정책](../../SERVICE_POLICY.md)

[일정](schedule.md)과 [근무 시간](work-hours.md)을 연결한 뒤 검증합니다. [확장 연결 안내](extension-setup.md), [자동 검사](ci-artifacts.md), [운영 환경](remote-operations.md)을 먼저 확인합니다. 이 문서의 항목을 운영 환경에서 확인하기 전에는 배포 완료로 기록하지 않습니다.

## 검증 절차

1. 검사한 Worker 번들을 검증 환경에 배포합니다. 확장 ZIP은 별도로 설치합니다. [Workers 배포 절차](../mcp/workers-release.md)를 따릅니다.
2. Chrome 프로필 두 개를 따로 승인하고 연결합니다. 각 연결 키로 연차, 일정, 근무 시간과 월 근무 요약을 확인합니다.
3. 브라우저 오프라인, 재로그인 필요, 접근 거부, 시간 초과를 각각 확인합니다.
4. 서비스를 중단한 뒤 이전 버전으로 되돌립니다. 다시 시작한 뒤 승인된 조회 한 건을 확인합니다.
5. 설치, 배포, 복구 절차와 검증 결과를 LLM Wiki에서 찾을 수 있게 연결합니다.

[산출물 검사](../utilities/verify-public-artifact.md)와 [서버 상태 확인](../utilities/get-service-readiness.md)을 재사용합니다. 로컬 빌드, 합성 연결, 실제 Chrome, 운영 환경의 결과를 구분합니다. 확인하지 못한 항목은 이유와 함께 남깁니다. 공개 증거에 실제 연차, 일정, 근무 시간과 접근 정보를 넣지 않습니다.

## 테스트 케이스

기능의 여러 단계가 함께 동작하는지 확인합니다. 기존 테스트로 표시한 경우를 제외하면 모두 예정입니다.

| TC | 확인 범위 | 준비와 실행 | 기대 결과 |
| --- | --- | --- | --- |
| TC-F-RELEASE-VERIFICATION-01 | 배포 검증 | Worker 번들을 배포하고 확장 ZIP을 별도로 설치합니다. | 두 앱을 서로의 소스 없이 설치하고 실행할 수 있습니다. |
| TC-F-RELEASE-VERIFICATION-02 | 배포 검증 | 서로 다른 Chrome 프로필에서 받은 연결 키 두 개로 조회합니다. | 각 결과가 그 키의 Chrome 채널에서 돌아옵니다. |
| TC-F-RELEASE-VERIFICATION-03 | 배포 검증 | 브라우저 오프라인, 재로그인 필요, 접근 거부, 시간 초과를 각각 재현합니다. | 네 상황을 구분합니다. 어느 경우에도 개인 결과를 성공으로 반환하지 않습니다. |
| TC-F-RELEASE-VERIFICATION-04 | 배포 검증 | 검증한 이전 서버와 확장 조합으로 복구합니다. 다시 연결한 뒤 연차를 호출합니다. | 예전 요청을 재실행하지 않습니다. 새 조회만 동작합니다. 결과를 LLM Wiki에서 찾을 수 있습니다. |
