# 실조회 방식과 공개 범위

[투두 7](https://github.com/freevue/flex-mcp/issues/7) · [서비스 정책](../../SERVICE_POLICY.md)

세 도구가 요구하는 결과를 얻을 수 있는 경로를 정합니다. 공개 소스, 공개 산출물, 제한 배포 산출물을 구분합니다. 본인 PC에서 읽기 경로를 확인했습니다. 회사의 허용 범위와 설치한 확장의 결과는 확인하지 않았습니다.

| 도구 | flex 공식 Open API에서 확인한 내용 | 본인 PC의 읽기 검증 |
| --- | --- | --- |
| 연차 | [연차 조회](https://developers.flex.team/reference/user-time-off-buckets-get-user-annual-time-off-buckets-by-employee-numbers)에 잔여 일수와 분이 있습니다. | 잔여량과 사용 가능량을 각각 읽었습니다. 두 값에 일·시간·분이 있었습니다. |
| 일정 | [공개 API 목록](https://developers.flex.team/llms.txt)에서 본인 기본 캘린더의 일반 일정 조회를 찾지 못했습니다. | 기본 7일 범위에서 빈 목록을 읽었습니다. 이번 달 전체에서 종일 일정을 읽었습니다. 시간 지정과 반복 일정은 실계정 표본을 확인하지 못했습니다. |
| 근무 시간 | [근무 스케줄 조회](https://developers.flex.team/reference/user-work-schedules-get-user-work-schedules-by-period-and-employee-numbers)는 일별 근무와 휴가 구간을 제공합니다. | 오늘, 이번 달 누적, 이번 달 전체의 실제·인정·소정·연장근무와 휴가 집계를 읽었습니다. 준비된 조회 함수는 휴무 요일과 날짜별 목표를 반환하지 않습니다. |

2026년 11월 6일, Ego Lite에서 사용자가 로그인한 Flex 계정 하나로 로컬 읽기 코드를 실행했습니다. 브라우저 밖으로는 확인한 필드와 표본의 유무만 반환했습니다. Flex 화면과 수치를 대조하거나 설치한 Chrome 확장과 MCP를 연결하지는 않았습니다.

같은 계정으로 본인 PC 전용 MCP도 확인했습니다. MCP 클라이언트에서 연차 두 잔액, 이번 달 기본 캘린더와 월 누적 근무 집계 다섯 개를 읽었습니다. 지정한 휴무 날짜가 월 목표에 들어 있는 경우에는 별도 근무 요약에서 그 날짜의 목표만 차감합니다. 이 방식은 표준 입출력으로 실행하며 로그인은 Ego Lite에 남습니다. 로컬 실행 파일과 휴무 날짜 설정은 공개 패키지에서 제외합니다.

이 확인은 설치한 Chrome 확장, 공유 서버 또는 Flex 화면과 수치를 대조하는 검증에 해당하지 않습니다.

Flex [Open API 이용 조건](https://developers.flex.team/reference/faq-limitation.md)에는 해당 요금제와 관련 권한이 필요하다고 나옵니다. 본인 브라우저에 로그인할 수 있다는 사실만으로 Open API 발급 권한이 확인되지는 않습니다.

## 첫 연동 범위안

첫 실조회 연동은 본인 Chrome 프로필 한 개에서 연차 한 건으로 시작합니다. 회사가 허용한 방식과 대상이 확인되면 [연차 조회](annual-leave.md)에 연결하고 화면의 두 잔액과 대조합니다. 그 뒤 [일정](schedule.md), [근무 시간](work-hours.md), [팝업 근무 요약](extension-work-summary.md)을 확인합니다. 이 범위안은 다중 사용자 배포를 포함하지 않습니다.

| 위치 | 처리 범위안 |
| --- | --- |
| Chrome | 로그인 자료와 계정 비교에 필요한 Flex 식별자는 Chrome 안에 둡니다. 브라우저가 현재 계정을 확인한 뒤 읽기만 수행합니다. |
| MCP 서버 | 인증한 사용자의 소켓으로 요청을 보냅니다. 도구 계약에 정한 결과만 요청 처리 중 메모리에 둡니다. 응답 본문은 로그나 디스크에 쓰지 않습니다. |
| MCP 클라이언트 | 승인한 호출에 필요한 결과만 받습니다. 대화 기록에 결과가 남는지는 사용하는 클라이언트의 보관 설정으로 확인합니다. |
| 공개 산출물 | 합성 자료와 공개 가능한 코드만 포함합니다. 비공개 조회 경로, 로그인 자료, 실응답과 개인 식별자는 포함하지 않습니다. |

본인 PC의 읽기 검증과 조직의 운영 승인을 구분합니다. 회사가 허용한 조회 방식, 배포 대상과 결과 보관 조건을 확인하기 전에는 실계정 연동을 공개 빌드나 공유 서버에 넣지 않습니다.

## 결정 절차

1. 회사 환경에서 허용한 조회 방식과 계정을 확인합니다. [Open API 이용 조건](https://developers.flex.team/reference/faq-limitation)도 확인합니다.
2. 허용된 방식에서 각 도구의 필수 결과를 확인합니다. 지원하지 않는 필드를 적습니다.
3. 산출물을 받을 대상과 전달 경로를 정합니다. Chrome Web Store를 선택하면 [사용자 데이터 정책](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq)을 확인합니다.
4. 브라우저, 서버, MCP 클라이언트가 받거나 보관하는 값을 기록합니다. 공개 파일에 넣을 수 없는 항목을 확인합니다.

승인한 Chrome 방식이 도구 계약에 맞으면 [연차 조회](annual-leave.md) 한 건부터 진행합니다. 공식 Open API가 필요한 필드를 제공하면 해당 도구의 후보로 기록합니다. 운영 범위에 맞는 방식이 없으면 미연결 상태를 유지합니다. 공개 이슈에는 선택한 방식과 검증 결과만 남깁니다. 이 결정 작업에는 별도 유틸이 필요하지 않습니다.

## 테스트 케이스

기능의 여러 단계가 함께 동작하는지 확인합니다. 기존 테스트로 표시한 경우를 제외하면 모두 예정입니다.

| TC | 확인 범위 | 준비와 실행 | 기대 결과 |
| --- | --- | --- | --- |
| TC-F-READING-BOUNDARY-01 | 정책 검토 | 공식 API가 잔여량만 제공하는 경우에 연차 도구의 필수 필드와 대조합니다. | 사용 가능량을 추정하지 않습니다. 제공하지 않는 필드와 대안을 결정 기록에 남깁니다. |
| TC-F-READING-BOUNDARY-02 | 정책 검토 | 실계정 조회 방식과 제한 배포 대상이 아직 승인되지 않았습니다. 공개 서버를 확인합니다. | 실계정 조회와 제한 배포를 시작하지 않습니다. 표준 입출력 서버는 미연결 상태를 유지합니다. 별도 원격 서버는 합성 데이터만 반환합니다. |
| TC-F-READING-BOUNDARY-03 | 산출물 검사 | 공개 산출물과 제한 배포 산출물의 허용 목록을 확인합니다. | 공개 파일에 내부 조회 경로와 실제 응답이 없습니다. 제한 배포 대상과 전송·보관 범위가 기록돼 있습니다. |
| TC-F-READING-BOUNDARY-04 | 정책 검토 | Chrome Web Store를 배포 경로로 선택한 경우를 검토합니다. | 사용자 데이터 처리 안내와 필요한 확장 권한을 확인할 항목으로 기록합니다. |
| TC-F-READING-BOUNDARY-05 | 본인 PC · 확인 | 로그인한 세션에서 준비된 읽기 코드로 연차, 일정, 근무 자료를 확인합니다. | 연차 두 잔액, 일정의 빈 목록과 종일 표본, 근무 집계 다섯 개의 유무만 기록합니다. |
