# 원격 MCP 운영과 복구

[투두 11](https://github.com/freevue/flex-mcp/issues/11) · [서비스 정책](../../SERVICE_POLICY.md) · [원격 중계](remote-bridge.md)

운영 환경은 Node.js 서버를 실행하고 HTTPS와 WSS 연결을 받을 수 있어야 합니다. 첫 버전은 서버 프로세스 하나를 사용합니다. 합성 검증은 [직접 검증](shared-connection-check.md)의 Node 명령으로 시작합니다. 운영 주소와 배포 대상은 실제 운영 작업에서 정합니다. 승인된 에이전트와 확장만 접속할 수 있게 합니다.

## 운영 확인과 복구

서버 준비 상태와 브라우저 상태는 [로컬 테스트](../../apps/mcp-server/test/relay.test.ts)에서 따로 확인했습니다. 같은 테스트에서 연결 끊김, 시간 초과, 대기 건수 상한을 확인했습니다. 운영 주소, 접속 신원 확인, 복구 시험은 남아 있습니다.

[서비스 상태 확인](../utilities/get-service-readiness.md)은 서버가 요청을 받을 수 있는지 확인합니다. 브라우저가 오프라인이면 조회는 실패합니다. 서버가 실행 중이라는 결과만으로 실제 조회가 가능하다고 보고하지 않습니다. 요청 시간 제한과 대기 건수 상한을 정한 뒤 두 동시 요청으로 확인합니다.

운영 로그에는 요청 ID와 오류 종류를 남깁니다. 응답 본문과 접근 정보는 기록하지 않습니다. 연결 끊김과 시간 초과를 구분합니다. 서버가 다시 시작하면 확장이 다시 연결할 수 있어야 합니다. 진행 중이던 요청은 되살리지 않습니다.

복구가 필요하면 새 조회를 먼저 중단합니다. 대기 요청을 종료합니다. 이전에 검사한 서버나 확장 버전으로 되돌립니다. 서버와 확장의 메시지가 맞지 않으면 두 산출물의 조합을 확인합니다. 상태 확인과 승인된 연차 조회 한 건을 확인한 뒤 운영을 다시 엽니다.

## 테스트 케이스

기능의 여러 단계가 함께 동작하는지 확인합니다. 기존 테스트로 표시한 경우를 제외하면 모두 예정입니다.

| TC | 확인 범위 | 준비와 실행 | 기대 결과 |
| --- | --- | --- | --- |
| TC-F-REMOTE-OPERATIONS-01 | 운영 검증 | 서버가 켜진 상태에서 승인되지 않은 에이전트와 브라우저로 각각 접속합니다. | 접속을 거부합니다. Chrome 조회를 실행하지 않습니다. |
| TC-F-REMOTE-OPERATIONS-02 | 운영 검증 | Chrome만 끊은 경우와 연결한 채로 응답을 지연한 경우를 확인합니다. | 서버 준비 여부와 브라우저 오프라인을 구분합니다. 연결 끊김과 시간 초과도 구분합니다. |
| TC-F-REMOTE-OPERATIONS-03 | 운영 검증 | 두 동시 조회와 설정한 대기 건수 상한을 넘는 요청을 보냅니다. | 두 요청을 섞지 않습니다. 상한을 넘는 요청은 브라우저에 전달하지 않습니다. |
| TC-F-REMOTE-OPERATIONS-04 | 운영 검증 | 서비스를 중단하고 검증한 이전 버전으로 되돌린 뒤 다시 엽니다. | 중단 중 새 조회를 받지 않습니다. 다시 연 뒤 승인된 연차 조회 한 건을 확인합니다. |
| TC-F-REMOTE-OPERATIONS-05 | 운영 검증 | 성공, 거부, 시간 초과 뒤 진단 로그를 확인합니다. | 요청 ID와 오류 종류만 확인할 수 있습니다. 개인 응답이나 접근 정보는 없습니다. |
